Quickstart

You can call the API from any HTTP client. All v1 routes use GET and return JSON. No API key is required.

Your first request

Fetch the first page of the feed with cURL:

cURL 
curl --request GET \
  "https://kmini-g-lang.vercel.app/api/v1/feed?page=1" \
  --header "Accept: application/json"

JavaScript

Fetch API 
const response = await fetch(
  "https://kmini-g-lang.vercel.app/api/v1/feed?page=1"
);
const result = await response.json();

if (!response.ok) {
  throw new Error(result.error?.code ?? "request_failed");
}

console.log(result.data.items);

Python

requests 
import requests

response = requests.get(
    "https://kmini-g-lang.vercel.app/api/v1/feed",
    params={"page": 1},
    timeout=40,
)
response.raise_for_status()
data = response.json()
print(data["data"]["items"])
i

The examples use the production API origin supplied for this project. The live request console below can help you inspect a response from your browser.

Authentication

The documented v1 endpoints are public and do not require an API key, bearer token, or session cookie.

AUTHORIZATIONNot required

Send requests directly to the endpoint.

HTTP METHODSGET

Other methods are rejected with 405 method_not_allowed.

CROSS-ORIGINCORS enabled

The handler allows cross-origin requests.

Requests & responses

The v1 contract is JSON over HTTPS. Collection responses use a data object and pagination metadata; single-resource responses wrap the resource in data.

Base URL

HTTPShttps://kmini-g-lang.vercel.app

Endpoints

Four stable v1 routes. Feed-origin posts and normal posts are intentionally separate resource types.

GET

List feed posts

Returns a paginated collection of feed-origin posts.

GET/api/v1/feed

Query parameters

NameTypeRequiredDescription
pageintegerNoPage number from 1 to 30. Defaults to 1.

Success response · 200

Returns FeedListResponse. Each item is a FeedPost with resource_type: "feed_post".

JSON · illustrative schema
{
  "data": {
    "items": [
      {
        "resource_type": "feed_post",
        "slug": "example-feed-entry",
        "title": "Example title",
        "url": "https://source.example/item",
        "content_type": "unknown",
        "media_count": 0,
        "image_count": 0,
        "video_count": 0,
        "media": []
      }
    ],
    "count": 1
  },
  "meta": {
    "page": 1,
    "has_next": false,
    "has_previous": false
  }
}

Illustrative values only. The field names and envelope follow the typed v1 model.

Possible errors

400 invalid_page · 405 method_not_allowed · 502 upstream_error / invalid_upstream_response · 503 service_unavailable · 504 upstream_timeout

GET

Search posts

Searches available content and returns matching feed posts and normal posts in a single result collection.

GET/api/v1/search

Query parameters

NameTypeRequiredDescription
qstringYesSearch query. Must contain non-whitespace text and be at most 200 characters.
pageintegerNoPage number from 1 to 30. Defaults to 1.

Example request

cURL 
curl --get \
  "https://kmini-g-lang.vercel.app/api/v1/search" \
  --data-urlencode "q=sample query" \
  --data-urlencode "page=1"

Success response · 200

Each search result includes its resource_type, slug, title, url, and content_type. thumbnail is optional.

JSON · illustrative schema
{
  "data": {
    "query": "sample query",
    "items": [
      {
        "resource_type": "post",
        "slug": "example-result",
        "title": "Example result",
        "url": "https://source.example/item",
        "content_type": "unknown"
      }
    ],
    "count": 1
  },
  "meta": {
    "page": 1,
    "has_next": false,
    "has_previous": false
  }
}

Possible errors

400 missing_query / query_too_long / invalid_page · 405 method_not_allowed · 502 upstream_error / invalid_upstream_response · 503 service_unavailable · 504 upstream_timeout

Pagination

Feed and search collection responses include a meta object. Pagination links point back to the public v1 endpoint, not the upstream content site.

FieldTypeAlways presentMeaning
pageintegerYesCurrent page number.
has_nextbooleanYesWhether another page is available.
has_previousbooleanYesWhether a previous page is available.
nextURL stringWhen availableAbsolute URL for the next page.
previousURL stringWhen availableAbsolute URL for the previous page.
!

The supported page range is 1–30. At page 30, the service does not advertise a next page.

Post model

FeedPost and NormalPost share fields, but remain distinct resources. Use resource_type to identify which resource you received.

FieldTypeRequiredDescription
resource_typestringYesfeed_post or post.
slugstringYesComplete resource identifier.
titlestringYesPost title.
urlstringYesCanonical source URL for the resource.
content_typestringYesMedia classification: unknown, image_gallery, video, video_collection, or mixed.
media_countintegerYesTotal number of media entries.
image_countintegerYesNumber of image entries.
video_countintegerYesNumber of video entries.
mediaarrayYesMedia entries. Empty collections are returned as [], not null.
descriptionstringOptionalPost description when available.
tagsstring[]OptionalAssociated tags when available.
channel_*stringOptionalChannel ID, name, username, and avatar metadata when available.
created_atstringOptionalSource-provided creation timestamp when available.

Optional source metadata is omitted when unavailable. Clients should not assume channel/profile/timestamp fields always exist.

Video & media

The media array is the canonical per-item representation. Top-level video fields mirror the first video item for convenience.

Media item fields

FieldTypeRequiredDescription
typestringYesimage or video.
urlstringOptionalMedia URL. For an enriched video this may be the direct file URL.
image_urlstringImage onlyImage source URL; required by model validation for image entries.
embed_urlstringOptionalEmbed/player page URL. It is not necessarily a direct video file.
video_urlstringOptionalDirect video file URL when available.
video_idstringOptionalSource video identifier.
thumbnailstringOptionalVideo thumbnail URL.
durationintegerOptionalDuration in seconds when available.
i

Direct media enrichment is best-effort. It is limited to approved HTTPS embed hosts, follows same-host redirects, uses a 15-second fetch timeout, and caps embed HTML at 4 MiB. A missing direct URL does not necessarily mean the post failed.

Errors

Errors use a consistent JSON envelope. Handle the stable error.code in application logic; use the message for diagnostics.

JSON · error response
{
  "error": {
    "code": "invalid_page",
    "message": "Page must be between 1 and 30."
  }
}
HTTPError codeMeaningWhat to do
400invalid_pagePage is malformed or outside 1–30.Send an integer between 1 and 30.
400invalid_slugSlug does not match the accepted format.Pass the complete alphanumeric, hyphen-separated slug.
400missing_querySearch query is empty or missing.Provide a non-empty q value.
400query_too_longSearch query exceeds 200 characters.Shorten the query.
404not_foundEndpoint or requested resource was not found.Check route and slug.
405method_not_allowedMethod other than GET was used.Use GET.
408request_canceledRequest was canceled before completion.Retry only if the client still needs the result.
500internal_errorUnexpected internal failure.Retry later; report persistent failures.
502upstream_errorUpstream source could not be reached.Retry with backoff.
502invalid_upstream_responseUpstream data failed response validation.Retry later; report persistent failures.
503service_unavailablev1 data service is not configured.Service-side configuration issue.
504upstream_timeoutService request exceeded its timeout.Retry with backoff.

Limits & behavior

The following constraints are defined by the v1 handler and typed service implementation.

PAGE RANGE1–30

Feed and search page values.

SEARCH QUERY200 characters

Measured as Unicode runes.

HANDLER TIMEOUT35 seconds

Per v1 service request context.

  • Only GET is supported by v1 endpoints.
  • Single-resource slugs must match letters and digits separated by single hyphens.
  • Feed and normal posts have different resource types and different routes.
  • Media counts and content classification are validated against the media array.
  • Empty media collections are represented as empty arrays.
  • Optional metadata is omitted when the source does not provide it.
  • No numeric rate limit is specified in the current v1 contract.
